## Phase 2 — fit and decisions
- **Scope check.** Fits the M-ART row (SPEC §12, edited to the D-15 trio in v1.9). No behaviour: the stage plays only the active character's `idle_a` loop (D-8; behaviour = M1). Review of the other two uses `--character=` and the dev lineup.
- **Frame 48 × H with headroom (ADR 009).** Width 48. H = the smallest of 52/56/60 such that every frame of every slot variant keeps rows 0 transparent (and ≥ 1 clear row above the tallest point: kitsune ears at the happy apex); provisional **48 × 56**, fixed in MA-23 by measurement. Feet stay on the same row, so the extra rows are pure headroom.
- **Sizing must not shrink.** `computeScale` today divides by `frameH`; with H = 56 the M preset would drop from ×4 to ×3. New optional manifest field `scaleRef` (px, default `frameSize.h`) = the standing-figure height used for sizing; built-ins write 48, so S/M/L stay ×3/×4/×5 (ADR 009). The `maxFraction` clamp keeps using the full frame height. Pure change in `src/core/scale.ts` (`refH` next to `frameH`).
- **Per-animation `anchor` (optional).** `sit_edge` (and `hang` in M1) pivot on the seat/hands, not the feet. The pose sets a `seat` joint and the builder emits `animations.sit_edge.anchor`. Manifest-only in M-ART (validated); the IPC payload carries it from M1, when surfaces exist. SPEC §5.1 edit after Q1 below.
- **Pack ids.** Built-ins are `pixmates.<id>` (rules/characters.md: prefix reserved, imports cannot overwrite), folder = id: `resources/characters/pixmates.maid/`. `src/shared/pack.ts` gets `BUILTIN_PREFIX` + `builtinPackId(rosterId)`; content keeps roster ids (`DEFAULT_CHARACTER = 'maid'`); the registry accepts only `pixmates.*` folders in packaged builds. `spike-*` stay dev-only until deleted in MA-31.

## Rig spec (written to `docs/art/RIG.md` in MA-20)
- **Coordinates:** 48-px units, origin = root at the feet (x 24 on a pixel boundary, feet row fixed); joints are integer offsets from their parent.
- **Joints:** root → hip → chest → neck → head → face; chest → shoulder L/R → hand L/R; hip → foot L/R; chest → back (tail/cloak); head → acc (ears/horns/clip); head → fx (mark anchor, emitted per animation for M1); hip → seat.
- **Slots and variants:** `head` (per character authored mask); `head_acc` `horns | fox_ears | clip` (antenna M3); `hair_back` `short | long` (chain); `torso`; `arms` mitten biped; `legs` `biped` (wheel M3 — contract only); `hem` `skirt | shorts` (chain lag); `back` `none | spade_tail | fox_tail` (cloak, wings M3+ — contract only); `neck_acc` `bow | choker | scarf`.
- **Body (`assets-src/characters/<id>/body.ts`):** joint rest offsets, chosen variants, ramps per material, part generators (procedural: cloth, back hair, fur, tail tube) and authored masks (head, fringe, horns/ears, shoes, bow/choker, face library).
- **Pose (`assets-src/rig/anims/<anim>.ts`, one file per animation, shared by all bodies):** per frame `{ root: {dx,dy}, joints?: Partial<Record<Joint,{dx,dy}>>, parts: { armL, armR, legs, hem? }` (variant ids e.g. `arm:swing_fwd`), `face: ExpressionId`, `squash: −2…+2` (whole rows inserted/removed under the chest, no resampling), `breath: 0|1` (sub-pixel chest colour shift), `order?: 'arms_front'|'arm_l_back'|…`, `impulse?: {x,y}` (chain kick) `}`. A body may override a pose only through a per-body `tweaks` table (offsets), never by forking the animation.
- **Composite order:** back → hair_back → legs/hem → torso → arms (by `order`) → head mask → head_acc → face layer → neck_acc; then outline, selective outline, AA, authored masks restored, rim (rules: passes run on the composite, so seams never show).
- **Frame names** `<character>/<anim>/<nn>` (sheets, tests, errors). The builder checks: palette-only px, row 0 transparent in every frame, frame counts = pose lengths, loops seamless (chain), atlas ≤ 1024², every manifest animation resolves.

## Face library (per character, `assets-src/characters/<id>/face.ts`)
- An expression = `{ eyes, brows?, mouth, cheeks }` masks on the face anchor; parts are reused across expressions, so a character authors ≈ 8 eye masks + 6 mouths, not 13 full faces.
- Expressions: `neutral`, `blink` (closed), `half` (half-lid, sleep-in/idle_b), `talk_a/b/c` (closed, small open, open «o»), `happy` (^^ eyes + open D-mouth with tongue), `worried` (raised inner brows, wavy small mouth), `think` (eyes glance up-side, flat side mouth), `sleep` (closed, small «o»), `startle` (>< eyes + «o»), `petted` (^^ + strong blush), `wince` (drag/fall: one eye squeezed).
- A test fails the build if a character misses any expression a pose references; face px never cover hair (ART-BIBLE §11).

## D-16 — three-quarter (3/4) travel view (owner, 2026-11-23; ADR 010 proposed)
- **Problem.** `walk` is front-facing (feet spread sideways, face to the viewer), but in M1 the character travels
  horizontally along the taskbar and window tops (SPEC §4.2–4.3): a front walk sliding sideways reads as a glide.
- **Fit.** M-ART scope (rig + 3 characters); no behaviour, the stage still plays only `idle_a` (D-8). Doing it now
  means kitsune and goth are authored once in both views, instead of reworking 3 bodies in M1.
- **Views.** `front` (all current poses) and `q34` (three-quarter, **authored facing screen-right**; left = runtime
  mirror about x = 24, light flip accepted, ART-BIBLE §8). No profile view, no back view.
- **Which animations get q34 (M-ART):** `walk` (8 @ 10, replaces the front walk) and `turn` (2 @ 10, one-shot:
  f0 = front body + q34 head and eyes leading, f1 = q34 rest stance). M1 plays `turn` forward before travel and in
  reverse after it (frame order is renderer logic, no format field). Stay front: `idle_a/b`, `talk`, emotions, `wave`,
  `petted`, `startle`, `sit_edge`, `sleep` (the character turns to the viewer to act or talk), `drag`/`fall` (carried,
  tumbling: no travel direction), `land` (lands, then `turn` if it walks on). M1, authored in q34 when built: `run`
  (fallback `run → walk` already q34), `climb` (q34 mirrored against the window side), stop-and-look idle if needed.
- **Front walk:** retired from the manifest (no M1 consumer: nothing walks toward the camera on a 2D desktop); the
  pose stays in git history. Alternative → Q-D16-1.
- **Manifest:** per-animation optional `facing: 'front' | 'right' | 'left'` (default `front`), zod-validated next to
  `anchor`; built-ins write `right` on `walk`/`turn`. M1 mirrors an animation when `facing` ≠ the travel direction
  and never mirrors `front` ones. Imported packs (M5) may ship a left-facing walk. `stage:characters` carries it like
  `anchor` (renderer ignores it until M1). Animation names stay flat (no `view` field in the pack: views are a rig
  concept, the runtime only sees strips + `facing`), so SPEC §5.1 stays one strip per name.
- **Rig (`RigAnim.view`, `PoseFrame.headView?`).** Per-view rest layout `REST.q34` in `rig/body.ts`: head joint +1 px
  toward facing (a constant lean, never animated — the head stays steady), face anchor +3 px toward facing, chest/hip
  axis unchanged; shoulders: near (screen-left) +1 px out, far (screen-right) −2 px in and 1 row lower; feet on one
  x line ±0 (stride is fore/aft along x). `Body.views.q34` (required for built-ins) = `{ head, face, masks, apron?,
  tweaks? }`; a body without it fails the build if any q34 pose is used.
- **Part masks per view.** Authored per character in q34: head (skull + fringe parted toward facing, far side lock
  hidden behind the cheek, near lock full, 2 px of back hair visible behind the nape), horns (near full, far shorter
  and behind the skull outline — they live in the head mask), fox ears (`head_acc` q34: near ear full, far ear 2 px
  narrower, 1 px lower), clip (on whichever side is near in the right-facing art; it swaps side when mirrored —
  accepted, noted on the sheet), neck_acc (bow/choker/scarf 1 px narrower, shifted toward facing), apron bib +
  panel (8 px, shifted +2), shoe q34 (5-px side shoe, toe forward). Procedural parts take view params: bodice
  half-width near 4.8 / far 3.6 (`curveX` centre +1), skirt/shorts hem with trailing flare, back hair mass +2 px
  trailing, fox tail / spade tail rooted 2 px to the trailing side and drawn behind, scarf ends trail (chain).
- **Depth order in q34:** far arm + far leg → back hair/tail → … → torso → near leg/hem → near arm (new draw order
  `q34`: far = R behind torso, near = L in front). Far leg 1 ramp step darker (depth), far arm visible only where it
  clears the torso (hand/cuff on `swing_fwd`).
- **q34 walk motion:** stride along x — contact feet 6–8 px apart fore/aft, passing foot lifted 2 px, contact foot
  planted ≥ 4 frames; 1-px bob; arms swing fore/aft (near arm in front of the torso, far hand peeking); hem trails
  1 px on the passing frames. **Head steady:** root dx = 0 and head-x − hip-x constant in every frame (the existing
  test extends to q34); only vertical bob/dip ≤ 1 px; hair, locks and tail carry the follow-through.
- **Face library per view.** `face.q34` = parts reused where possible: near eye full width, far eye 1 px narrower
  (foreshortened) and 1 px closer to the profile edge, mouth shifted 2 px toward facing, blush near cheek only.
  Required q34 expressions = those referenced by q34 poses: **`neutral`, `blink`** (walk, turn). `happy` and
  `worried` in q34 → Q-D16-2 (M1 needs them for chasing the cursor / fleeing).
- **Gates extend to q34 frames:** headroom (row 0 + H re-measured incl. q34 ears/horns), seam test, `validateFace`
  per view (face px never over hair of the q34 head mask; outside-head px), `armTorsoContrast` on every q34 frame
  (near arm: full rule; far arm behind the torso: separator on its visible edge, arm-end rule only when ≥ 3 sleeve px
  are visible), mirror test (mirrored q34 frame = exact column flip about x = 24, same alpha count).
- **Shared LATER items (art-director, maid round 3):** think fist 1 px toward its own arm + a 2-px darker outline
  break between fist and jaw (+ optional 1-px knuckle highlight); `idle_a` face micro-variation = one frame of a new
  required expression `glance` (neutral with irises 1 px toward facing side); `sit_edge` pointed boot toe gets a 1-px
  light highlight in `pointToe`. All in the shared rig, so kitsune and goth inherit them.
- **Budget:** 103 frames − 0 (walk stays 8, now q34) + `turn` 2 = **105 frames**, 16 animations (113 if Q-D16-1 keeps
  `walk_front`). Shelf atlas stays ≈ 1008 × 336–392 (≤ 1024² holds 378 frames; M1 adds run/climb/hang/peek +
  signatures ≈ 70 → ≈ 1008 × 504). RGBA ≈ 1.4–1.6 MB per character, one resident (D-8): +≈ 0.3 MB decoded vs today,
  inside the ≤ 265 MB target (spike maid 257.5 MB, cap 280). Idle CPU unchanged (frame timer only).
- **Design checks.** (a) core: none in M-ART; M1 core decides facing from travel direction and emits `turn` → `walk`.
  (b) content: none (fps/frames are rig data). (c) IPC: `facing` optional on `stage:characters` animation entries,
  both ends + contract test via `/ipc-channel`, main takes it from the validated manifest only. (d) DB: none.
  (e) untrusted: imported `facing` is an enum in `manifestSchema`; nothing reaches a prompt. (f) perf: above.
  (g) i18n: none. (h) animations: q34 `walk`, `turn`; expressions `neutral`/`blink` q34 + `glance` (front); rig poses
  q34 rest, arm swing fore/aft, legs fore/aft, `q34` draw order.
