# M0 — Каркас і спайки (план)

- Дата: 2026-11-22 · SPEC v1.2 §1, §2, §3, §10, §11, §12 (M0), §13 · ADR 001, 002 · рішення D-6, D-8
- Ціль: робочий захищений каркас Electron 45 + electron-vite з трьома вікнами, typed IPC, чистим ядром, CI і `pnpm perf`; три спайки з виміряними числами → ADR 007 (вікна), ADR 008 (SQLite), нотатка про GPU-прозорість.
- Поза M0: стейт-машина поведінки, фізика, риг і арт (M-ART/M1), electron-store і налаштування (M5), NSIS/автооновлення/e2e (M6), AI (M2).

## Критерії приймання
1. `pnpm dev`: прозорий placeholder-спрайт поверх усіх вікон; кліки поза непрозорими пікселями проходять у вікна під ним (браузер, Провідник, панель задач); drag тягне спрайт і не забирає фокус з активного вікна. Перевіряє власник очима + скріншот на світлих і темних шпалерах.
2. `pnpm typecheck && pnpm test && pnpm lint && pnpm format:check` зелені локально; GitHub CI зелений: `check` (ubuntu), `build` (windows-latest), `secrets` (gitleaks).
3. Тести: детермінізм `step` (той самий seed + події → той самий state + effects), golden-значення RNG, контракти IPC (відхиляє зайві поля, oversize, чужого sender), ESLint-межі core = правила `core-purity.mjs` 1:1 (lint-тест із фікстурою).
4. `pnpm perf` на зібраній збірці (`--dir`): idle placeholder **< 2% CPU** (середнє за 120 с) і **≤ 280 MB** суми приватної пам'яті усіх процесів (ADR 007; спершу було ≤ 200 MB working set — змінено рішенням D-12) → `reports/perf/2026-11-xx.md`.
5. ADR 007 і 008 мають статус Accepted і містять виміряні числа; `docs/plans/spikes/s1…s3.md` записані; SPEC §2 (сховище) і §3.1 (вікна) оновлені під рішення.
6. Hook `electron-hardening.mjs` мовчить на всьому `src/main` і `src/preload`; `electron-security-reviewer` без блокерів.
7. `docs/CONTEXT.md` (статус, ✅ у мапі, gotchas) і команди в `CLAUDE.md` відповідають `package.json` (`/sync-context`).

## Дизайн
- **TS-проєкти** (`tsconfig.base.json` як у Cossack Kin + `erasableSyntaxOnly`, `verbatimModuleSyntax`, `exactOptionalPropertyTypes`):
  `core` (src/core, src/content, src/shared; `lib: ES2023`, `types: []` — DOM і Node недоступні на рівні типів) · `main` (src/main; `types: [node]`) · `preload` (src/preload; DOM + node, бо типи `electron` посилаються на NodeJS) · `renderer` (src/renderer; DOM, `react-jsx`, `vite/client`) · `tools` (tools/, конфіги; node) · `tests` (tests/; node + DOM). `typecheck` = `tsc -p` для кожного.
- **ESLint**: конфіг Cossack Kin (strictTypeChecked, `no-eval`, `no-new-func`, `local/require-disable-reason`, `reportUnusedDisableDirectives`) + межі: core/content/shared не імпортують electron/node:*/pixi/react/main/renderer/preload, без clock/random/timers/globals (теги `core-purity[<rule>]`: `platform-package`, `node-builtin`, `outer-layer`, `clock`, `random`, `browser-global`, `timer`, `require`); renderer і preload не імпортують `src/main` і `node:*`; main не імпортує renderer. `tests/unit/lint/core-purity.test.ts` — копія підходу Cossack Kin.
- **Вікна** (`src/main/windows/secure.ts` — єдина фабрика): `contextIsolation`, `sandbox`, `nodeIntegration: false`, `webSecurity`, без webview; `web-contents-created` → deny `will-navigate`, `setWindowOpenHandler` → deny, `will-attach-webview` → prevent; `session.setPermissionRequestHandler`/`setPermissionCheckHandler` → deny; `requestSingleInstanceLock` (друга копія → показати stage). CSP як `<meta>` у кожному HTML (`default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data: blob:; connect-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'`), у dev — послаблена через vite-плагін (`ws:` для HMR, `unsafe-inline` для React refresh), як у Cossack Kin. Pixi під CSP: `import 'pixi.js/unsafe-eval'` + `Assets.setPreferences({ preferWorkers: false })` (gotcha Cossack Kin). Stage — завжди живе; chat — лінивий, ховається на close; settings — створюється/знищується. Chat і settings у M0 — React-заглушки.
- **IPC** (`src/shared/ipc.ts`): реєстр каналів `{ name, kind: 'invoke'|'send', request, response?, windows: WindowRole[] }`, усі схеми `.strict()` з межами довжин. M0-канали: `app:ping` (invoke, усі вікна), `stage:hit` (send, `{ overOpaque: boolean }`, лише stage), `stage:input` (send, `{ kind: 'drag-start'|'drag-end'|'click' }`, лише stage). `src/main/ipc/handle.ts`: перевірка sender (webContents id ∈ ролі каналу + `senderFrame.url` = очікуваний origin), `safeParse`, результат `{ ok: true, data } | { ok: false, code: 'invalid'|'forbidden'|'internal' }`, без стеків. Preload на вікно (`src/preload/{stage,chat,settings}.ts`) експонує `window.pixmates` з іменованими функціями; збірка preload — CJS (sandbox), перевірити налаштування electron-vite 6.
- **Core** (ADR 002): `rng.ts` (seeded, стан — число в `CoreState`), `types.ts` (`CoreState`, `CoreEvent` = `tick | input`, `Effect` = `PlayAnimation | SetHitThrough`), `step(state, event, now) => { state, effects }`. У M0 main викликає `step` лише на події вводу (без 10 Гц циклу — це M1). Числа (немає) → `src/content/` з'явиться в M1.
- **i18n**: `src/i18n/locales/{uk,en}.json` з ключами `tray.show`, `tray.hide`, `tray.chat`, `tray.settings`, `tray.quit`, `hotkey.conflict`; мінімальний i18next у main (повний UI-i18n — M5).
- **Перевірки (a–h)**: (a) core вирішує лише drag-стан і анімацію placeholder; main інтерпретує `SetHitThrough` → `setIgnoreMouseEvents`. (c) три канали вище. (d) БД у M0 немає (лише спайк). (e) недовірений ввід — лише IPC від renderer. (f) idle: ticker на вимогу, без циклів у main. (g) ключі вище. (h) один placeholder-кадр, без ригу.

## Спайки
**S1 — вікна: A (overlay на `workArea`) vs B (вікно ~160×160, що рухається)** → ADR 007. Обидва з одним placeholder і однаковим `maxFPS`. B: renderer інтерполює, main рухає вікно `setPosition` (цілі px) 60 Гц лише під час ходьби; click-through у B теж через alpha hit-test (прозорі кути).
- Вимір (`pnpm perf --scenario idle|walk`): CPU avg/p95 і сумарний WS для idle і для «ходьба 1000 px туди-назад 60 с».
- Плавність: інтервали кадрів (A: rAF у renderer; B: інтервали `setPosition` у main), p95 і кількість пропусків > 33 мс; + оцінка власника очима (125% і 150% масштаб).
- Click-through (чекліст власника): клік, ПКМ, колесо, hover-тултіп у браузері/Провіднику/панелі задач під overlay; над піднятим admin-вікном (`forward` у Windows ламається на вищому integrity level — задокументувати).
- Режим «лише на столі» (D-9): обидва варіанти без always-on-top — вікно лишається під іншими, не виходить наперед при кліку/drag (`focusable: false`, `showInactive`), видно при Win+D і згорнутих вікнах.
- Drag без фокуса: тягнути під час набору в Блокноті — фокус лишається, ввід не губиться; поверх панелі задач і fullscreen-вікна.
- Правило: **A**, якщо проходить усі пункти click-through і drag, CPU idle у бюджеті і не гірший за B більш ніж на 0,5 п.п.; інакше **B**, якщо він проходить і p95 `setPosition` ≤ 20 мс без видимого ривка; нічия → A (FX і бульбашки без зайвих вікон). Записати також RAM-різницю.

**S2 — SQLite: `node:sqlite` vs `better-sqlite3` 13 в main Electron 45** → ADR 008. Node 24.22 в Electron: `node:sqlite` без прапора, але не stable (RC лише з Node 25.7).
- Чи вантажиться в main у `pnpm dev` і у запакованому `--dir` (asar) без прапорів; чи є ExperimentalWarning; WAL, транзакції, prepared statements, `user_version` для міграцій.
- Бенч у `userData`: холодне відкриття, 10 000 insert в одній транзакції, 1 000 вибірок за індексом (медіана 5 прогонів); ΔRAM main; Δрозмір `win-unpacked`.
- Вартість збірки better-sqlite3: потрібен запис у `allowBuilds`? prebuild під ABI Electron без node-gyp? `asarUnpack`; CI `build` зелений.
- Правило: **`node:sqlite`**, якщо працює в запакованій збірці без прапорів, підтримує WAL/транзакції і не гірший за better-sqlite3 більш ніж у 2× на бенчі; інакше better-sqlite3. В обох випадках доступ лише через `storage/db.ts` (інтерфейс), щоб заміна була дешевою.

**S3 — GPU-прозорість + compat mode** → нотатка в CONTEXT gotchas (+ SPEC §3.1, якщо змінює поведінку). На машині власника (iGPU/dGPU, якщо є гібрид — обидва через налаштування графіки Windows): фон прозорий чи чорний (electron#40515), з DevTools закритими; той самий прогін з `--compat-mode`: прозорість + CPU idle/ходьба (софтрендер дорожчий). Правило: compat mode лишається ручним перемикачем; автодетект — лише якщо знайдемо надійну ознаку (`app.getGPUFeatureStatus()`), інакше підказка в M5. Друга машина/VM — за можливості власника.

## Ризики й фолоу-апи
- Security follow-up (M1, рев'ю 2026-11-22): L2 — `content-security-policy` заголовок у відповіді `app://` для html/svg (спільна константа CSP для `tools/` і `src/`); L3 — `realpath`-перевірка junction/symlink у неупакованій збірці.
- CSP через `<meta>` на `file://` у prod; перехід на власний протокол (`protocol.handle`) з HTTP-заголовками — оцінити в M6.
- Сума WS завищує спільні сторінки; в звіті поруч private bytes; бюджет SPEC рахуємо за WS (суворіше).
- `forward: true` над admin-вікнами — обмеження Windows, не баг; README у M6.
