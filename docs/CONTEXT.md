## 5. Gotchas
- `ELECTRON_RUN_AS_NODE=1` is set in shells spawned by VS Code/Claude Code: `electron-vite dev` then starts Electron as plain Node. Run `env -u ELECTRON_RUN_AS_NODE pnpm dev` there. The packaged build ignores it (RunAsNode fuse off — verified).
- `electron@45` has **no install script**: `pnpm install` does not fetch the binary; the first `require('electron')` (pnpm dev) downloads it, or `pnpm exec install-electron`. CI does not need it (electron-builder downloads its own zip). `allowBuilds` only denies `electron-winstaller` (Squirrel 7-Zip picker, unused).
- Preloads: with `type: module` electron-vite 6 emits ESM `.mjs` preloads, which sandboxed preloads cannot load → config forces `format: 'cjs'`, `[name].cjs`, `isolatedEntries`, `externalizeDeps: false`. Preloads import channel names from `shared/ipc-channels.ts` (zod-free; importing `ipc.ts` inlined ~160 kB of zod into each preload).
- `screen`, `Tray`, `globalShortcut` only after `app.whenReady()`; StageController reads display metrics lazily (guard test).
- Stage renderer subscribes to `onScale` before any `await` (main pushes on `did-finish-load`, which can beat Pixi init).
- Vite dep pre-bundling on first dev run triggers a full reload; `optimizeDeps.include` lists pixi/react to avoid it.
- Renderer pages load from the privileged `app://renderer/<role>/index.html` scheme (`windows/app-protocol.ts`: registered before ready, `protocol.handle` after; only files inside `out/renderer` with a known MIME type), never `file://`. The IPC sender check expects these URLs; CSP `'self'` = `app://renderer`. Fuses `GrantFileProtocolExtraPrivileges` off, `EnableCookieEncryption` on (read back from the exe). The URL parser folds `..` at the root, so traversal lands inside `out/renderer` (404).
- Lifecycle goes through `app/lifecycle.ts` (`registerLifecycle`): `second-instance` is ignored before ready; display listeners are added in `ready` and removed by its teardown on `before-quit`. Packaged builds quit on `--remote-debugging-port`/`--inspect*` (`app/launch-guard.ts`; Chromium still opens the port for a moment before main quits).
- Single-instance lock is per userData: a running `pnpm dev` makes any other launch (packaged too) quit at once. Use `--user-data-dir=<temp>` for side-by-side runs; `pnpm perf` does that itself.
- `pnpm perf` memory verdict = **private-bytes sum, avg ≤ 280 MB** (ADR 007); working-set sum avg/p95 is printed alongside (double-counts shared pages, ~350 MB in every mode).
- Spikes S1/S3: the overlay's GPU-process private memory scales with work-area size (124 MB vs 58 MB for a sprite-sized window). Main-process timers tick at 15.6 ms on Windows, so per-frame motion must be driven by renderer rAF. `setPosition` at 125 % drifts the window size (use `setBounds`). Pixi `maxFPS = 60` skips vsyncs on 60 Hz panels (M1: uncapped ticker + own throttle). `getGPUFeatureStatus()` is not a reliable WebGL/transparency signal; `capturePage` alpha proves page transparency, not desktop transparency. Compat mode + overlay walking ≈ 16 % CPU.
- S2: `node:sqlite` has no `transaction()` helper — `storage/db.ts` wraps BEGIN/COMMIT/ROLLBACK; no ExperimentalWarning in Electron 45; re-run the bench on each Electron major.
- Stage imports only named Pixi exports and inits with `skipExtensionImports: true` (no accessibility/DOM/events/filters bundle). Pixi events are not used: input is plain DOM listeners. Anything that needs a Pixi extension must import its `pixi.js/<ext>` init explicitly.
- Never screenshot the owner's whole desktop; use `pnpm dev -- --capture-stage=<dir>` for stage images.
- M-ART commands: `pnpm sprites` builds `resources/characters/<id>/` (git-ignored, deterministic, prints SHA-256; `pnpm build` runs it first). `pnpm sprites:sheet [<id>]` writes contact sheets, `pnpm sprites:preview` writes real-size APNGs over 4 backdrops (`reports/sprites/`). `node tools/sprites-sheet.ts --lineup` writes `reports/art-spike/lineup-real-size.png`, and `--swatch` writes `docs/art/palette.png`. `pnpm sprites` also builds `resources/fx/` (FX marks, git-ignored, not shipped; `pnpm sprites fx` = FX only). `pnpm sprites:sheet --review` / `pnpm sprites:preview --review` render the rig review bodies (`rig-dummy-a`, `rig-dummy-b`, `rig-maid48-preview`; never built into resources/), `pnpm sprites:sheet --fx` writes `fx-sheet.png` + marks composited at the `fx` anchor (incl. `fx-on-pixmates.maid.png`). `node tools/sprites-sheet.ts --real [<id>]` writes `<id>-real.png` (built-ins at real M scale on 4 backdrops: first frame of every anim + walk and its runtime mirror). Dev flags: `--art-lineup` (2 spike variants, blind A–D; key in `reports/art-spike/key.txt`, delete it to reshuffle), `--character=<id>`, `--anim-cycle`. `pnpm perf -- --character=spike-maid-64soft` copies that spike pack into `release/win-unpacked` and launches with `--perf-spike`.
- Stage IPC is now `stage:characters` (`onCharacters`; `stage:scale` is gone). Atlases load via `fetch('app://characters/<id>/sprites/atlas.png')`: the scheme has `corsEnabled`, and the host returns `Access-Control-Allow-Origin` only for `app://renderer` and the trusted dev origin; CSP `img-src`/`connect-src` include `app://characters`. Without a built `maid` pack the stage shows the M0 placeholder (until phase 2).
- Spike packs (`spike-*`) are listed only when unpackaged (or with `--perf-spike`); electron-builder `extraResources` excludes them.
- Spike heads are authored masks (`assets-src/spike/maid-{48,64}/rig.ts`: head, face layers, bow, shoe, spade); `maid.ts` stamps them after compose and restores them after outline/AA (tones final, posterize skips them). A face px never covers hair (brows show only through fringe gaps).
- Stage canvas = exact device-pixel box (`ResizeObserver` with `device-pixel-content-box`): `resizeTo: window` used whole-CSS-px `innerWidth/innerHeight` and resampled the canvas at 125 %. Check fractional scales with `pnpm dev -- --force-device-scale-factor=1.25 --capture-stage=<dir>` (the capture works in device px and records `scaleFactor`).
- `app://` reads go through `readContainedFile` (no symlinks/junctions, real-path containment, size check + read on one handle); the characters host serves only each pack's registered atlas.
- One style preset: `SOFT` in `assets-src/rig/style.ts` (cel, `celSnap`, `maskTones` deleted in MA-22). Rig gotchas: masks are stamped over procedural parts, so raised hands must stay outside the head mask (x ≤ 10 / ≥ 38); a seam closer fills enclosed gaps ≤ 3 px (pinholes where leg and shoe outlines meet); `computeScale` clamps on `refH` too (with the full 56-px frame L would drop to ×4 at 1080p/125 % — MA-21 deviation); the plan's frame table sums to 103, not 111; H = 56 is re-measured by `tests/unit/art/rig.test.ts`. Long bash heredocs fail in the agent shell here — write a script file and run it. Keep ≥ 1 skin row between fringe tips and the lash line (tips touching the lash read as a frown). Stale generated packs with old ids must be deleted from `resources/characters/` by hand (build-sprites does not prune).
- Arm over torso: `node tools/rig-contrast.ts [<body id>]` prints per-pose ΔL / shoulder-trim ΔL / separator / arm-end numbers (`pixmates.maid` included); `python3` here is the Windows Store stub (silently does nothing) — use `python`; the same check runs in `rig.test.ts`. Arm part ids are per side (9/10/11 L, 19/20/21 R; 11/21 = cuff + hand + chin fist). A body that puts its sleeves on the bodice ramp at the bodice shade fails the build.
- Master palette has an `fx_red` ramp (anger vein only; FX_OUTFIT maps the unused `horn` slot to it). FX marks may set `outline: null` (self-outlined masks). `pnpm sprites` validates every manifest with `manifestSchema` / `fxManifestSchema` before writing. `simulateChain` takes `loop` (one-shot clips: no warm-up, no seam spread); the composer's `prev` joints for frame 0 of a one-shot clip are the frame itself.
- Art determinism: `assets-src/` code may only use seeded hashes, integer math and + − × ÷ / sqrt (no sin/cos/pow into output). Bash heredocs with template literals sometimes fail to parse in this shell, so write helper scripts with the Write tool.
