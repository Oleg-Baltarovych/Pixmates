# SPEC v1 — ревʼю (2026-11-22)

> **Статус: опрацьовано (2026-11-22).** Рішення власника внесено в `docs/SPEC.md` v1.1 і ADR 001–006. Назва — **Pixmates** (D-1). Лише Windows (D-2). Dev companion у v1 (D-3). 10 оригінальних персонажів на ризі, без дефолтного Домовика (D-4). AI SDK (D-5). Вікно — за спайком M0 (D-6). D-7 відкрите. AI-tooling побудовано (`CLAUDE.md`, `.claude/`, `docs/AI-WORKFLOW.md`; у §8 нижче — початкова пропозиція: `skins.md` став `characters.md`, додано `dev.md`).
> Технічні факти перевірено в мережі 2026-11-22 (npm registry, офіційні доки, GitHub API), не з памʼяті.

Загальний висновок: **ідея реалізовна, і стек обрано правильно.** Electron тут кращий за Tauri: у Tauri v2 немає click-through з пересиланням руху миші (issue #11461 закрито як «not planned»). Без цього альфа-хіт-тест працює лише через полінг курсора.
Архітектура «логіка в main, renderer лише малює» і read-only tools — сильні сторони SPEC.
Слабких місць три:
1. **Бюджет ресурсів нереалістичний для Electron.**
2. **Рух вікна з main на 10 Hz виглядатиме ривками.**
3. **У продукту немає відмінності від десятків існуючих AI-петів.**
Головний урок із Cossack Kin стосується арту: «простий» арт там відкинули, тож персонаж потребує арт-спайку на самому початку.

## 1. Ринок і позиціонування

| Продукт | Що вміє | Чого бракує |
|---|---|---|
| BongoCat (Tauri, ~25k ★) | Live2D-кіт, реагує на клавіатуру й мишу | немає AI, не знає про систему |
| VPet-Simulator (WPF, Steam) | моди, анімації, плагіни | тільки Windows, чат другорядний |
| Clippy (Felix Rieseberg, Electron) | локальні LLM | це чат-вікно, а не жива істота; сам автор називає його сатирою |
| Desktop Mate (Steam) | 3D, ліцензовані IP | немає LLM і користі |
| Peekoo, Tamago AI, DeskCat… (open source) | пет + LLM-чат + pomodoro | дрібні, сирі |
| claude-pet, deskling, hearthling, woofy… | реагують на Claude Code через hooks | одна платформа, 0–12 ★, лише індикатор статусу |

**Ніша:** ніхто не поєднує в одному відшліфованому крос-платформному персонажі (1) живого піксельного пета з фізикою, (2) реальну обізнаність про систему, (3) користь (фокус, нагадування), (4) LLM з tools і (5) **сигнали розробника**: Claude Code hooks, git, CI.
Пункт 5 — це твій AI-native workflow із резюме, перетворений на продукт. Він дає проєкту історію: «компаньйон, який бачить, що роблять твої AI-агенти».

### P-01 · Додати «Dev companion» як окремий етап (рекомендація)
- **Claude Code hooks → пет:** `PermissionRequest` (агент чекає дозволу) → персонаж махає і показує «потрібен ти», `Stop` → «готово», `PostToolUseFailure`/`StopFailure` → засмучений, `SubagentStart/Stop` → «кличе помічників».
  Підключення: однорядкова команда в налаштуваннях генерує hook-конфіг, який шле подію на локальний endpoint.
- **Локальний MCP-сервер** (`@modelcontextprotocol/server` v2): інструменти `say`, `emote`, `notify`, щоб будь-який агент міг «попросити» персонажа щось сказати. Слухає лише localhost, авторизація токеном, перевірка `Origin`/`Host` (захист від DNS rebinding).
- Опційно: стан git у поточному репо, статус GitHub Actions через `gh` або polling.

Тут прямо переноситься твій досвід із push-платформи: пріоритети подій, анти-спам, cooldown, тихі години. Це та сама задача «не засипати користувача сповіщеннями», тільки на десктопі.

## 2. Технічні знахідки (T-)

### T-01 · Бюджет «< 150 MB RAM» для Electron недосяжний (§1, §13)
Electron 45 на холостому ходу з одним прозорим вікном займає ~100–300 MB залежно від способу вимірювання. Три живі вікна (pet + chat + settings) майже напевно перевищать 150 MB.
**Пропозиція:**
- Постійно живе лише pet-вікно. Chat створюється ліниво і ховається (не знищується: так швидше відкривається), settings створюється і знищується щоразу.
- Бюджет переформулювати як **≤ 200 MB сумарно (всі процеси) у простої, виміряно на зібраній збірці** скриптом `pnpm perf`.
- CPU < 2% лишається реальною ціллю (див. T-03).

### T-02 · Рух вікна з main на 10 Hz дає ривки (§3.1, §4.1)
SPEC пропонує вікно 256×256, яке main пересуває через `setPosition` на тіку 10 Hz. Ходьба й падіння виглядатимуть ривками. Якщо ж рухати 60 разів на секунду, на Windows бувають мерехтіння і зайве навантаження на DWM.
**Варіанти (вирішує спайк у M0):**
- **A. Overlay на дисплей:** одне прозоре click-through вікно на весь `workArea`, персонаж — спрайт усередині canvas. Рух плавний і дешевий, легко додати кілька персонажів, частинки й бульбашки. Ризик: композитинг повноекранного прозорого шару (міряємо). Відомий баг macOS з overlay, що тротлить вікно під ним, виправлено в Electron 43+.
- **B. Маленьке вікно:** рух інтерполюється в renderer, а main лише виставляє позицію на 30–60 Hz під час руху.
Рекомендую A як ціль і B як запасний варіант. Рішення фіксується ADR після вимірів (CPU, RAM, плавність, клікабельність вікон під overlay).

### T-03 · Рендер: не 60 fps (§2)
Піксель-арт анімується на 6–12 fps. Pixi `ticker.maxFPS` має відповідати поточній дії: ~12 fps у спокої, 30–60 лише під час фізики, 2 fps або повна пауза у `sleep`/`hidden`. Кадр рендериться лише тоді, коли він змінився.
Саме це дає < 2% CPU.

### T-04 · Поведінка — чисте ядро, як у Cossack Kin (§3, §4)
`BehaviorEngine`, фізику, настрій, cooldown/анти-спам і планувальник винести в `src/core/`: чистий детермінований TS, `now` і RNG передаються ззовні, без імпортів Electron/Node/DOM. Main лише підключає сенсори до ядра.
Так вийде unit-тестована стейт-машина з пріоритетами, і перенести hook `core-purity.mjs` з Cossack Kin можна майже без змін.
Власна стейт-машина замість XState: менше залежностей, детермінізм, і краще показує твою роботу.

### T-05 · LLM-шар: Vercel AI SDK замість трьох ручних адаптерів (§6.2)
`ai` 7.x + `@ai-sdk/anthropic` + `@ai-sdk/openai-compatible` + `ai-sdk-ollama` дають стрімінг, tool calling і structured output для всіх трьох провайдерів.
Власний код зосереджується на тому, що цінне для резюме: агентний шар (персона, контекст, памʼять, tools, бюджет, перетворення подій на репліки). Ручні адаптери — тижні роботи без видимого результату.

### T-06 · Сховище: перевірити `node:sqlite` перед `better-sqlite3` (§2)
`better-sqlite3` 13.x уже має N-API prebuilds, але це все одно нативний модуль: розпаковка з asar, ризики при пакуванні. Electron 45 працює на Node 24. Якщо `node:sqlite` доступний і стабільний у main-процесі, нативна залежність не потрібна. Перевірити на спайку M0. `electron-store` 12 тепер ESM-only, треба це врахувати в збірці main.

### T-07 · Безпека LLM: prompt injection через дані системи (§6.3, §9)
Заголовки вікон, буфер обміну, назви процесів і події з hooks — **недовірений текст**, який іде в промпт. Read-only tools сильно знижують ризик, але потрібні ще такі заходи:
- Недовірені дані передаються в окремих блоках із розмітником, ліміт довжини.
- Tools, що діють (`start_pomodoro`, `set_reminder`), мають ліміти і видимий слід у UI.
- MCP/HTTP-endpoint (P-01) приймає лише фіксовані схеми подій, без вільного тексту в системний промпт.
- `say` з MCP показується як цитата від агента, а не як голос персонажа.

### T-08 · Платформи й підпис (§2, §12)
- «Суто десктоп»: пропоную **Windows 11 → macOS 14+**, Linux прибрати з v1 (Wayland ламає click-through і позицію вікон).
- Автооновлення: на Windows `electron-updater` працює і з непідписаною NSIS-збіркою (з попередженням SmartScreen). **На macOS автооновлення без Apple Developer ID ($99/рік) не працює.** Для v1: macOS — ручне завантаження dmg, і це записується в README.
- Відомий баг Windows: чорний фон замість прозорості на частині GPU з апаратним прискоренням (electron#40515). Потрібен перемикач «сумісний режим» у налаштуваннях.

### T-09 · Дрібниці
- `active-win` застарів, тепер `get-windows` 10 (ESM). На macOS заголовок вікна потребує Screen Recording, тому за замовчуванням ці перевірки вимкнені (і так збігається з налаштуваннями приватності).
- Global hotkey `Ctrl+Shift+Space` конфліктує з деякими IME/апками: потрібна перевірка реєстрації і повідомлення про конфлікт.
- `focusable: false` у pet-вікна + drag: перевірити на спайку, що drag працює без фокуса на Windows.

## 3. AI в персонажі — як зробити круто (P-02)

Принцип: **персонаж, а не чат-бокс з аватаркою.** AI має керувати тілом, а не лише генерувати текст.

1. **Відповідь = текст + тіло.** Через structured output модель повертає `{ say, emotion, action? }`. `emotion` береться з фіксованого набору анімацій скіна (`happy`, `think`, `worried`, `proud`…). Персонаж «думає» (`think`), поки йде tool call, говорить зі стрімінгом і закінчує жестом. На моделях без structured output — fallback через легкий тег у тексті.
2. **Ініціатива без спаму.** Ланцюжок: подія сенсора → ядро вирішує, *чи* говорити (пріоритет, cooldown, ліміт 1/10 хв, тихий режим) → репліка береться з **шаблонів скіна** (безкоштовно, офлайн, миттєво). LLM лише за бажанням перефразовує шаблон з урахуванням контексту, у межах денного бюджету токенів. Персонаж живий і без ключа.
3. **Контекст, а не памʼять усього.** У кожен запит іде: персона скіна, стисле зведення стану (настрій, час доби, фокус-сесія, головні показники системи) і 3–7 «фактів про користувача». Факти лежать у SQLite і видимі/редаговані в налаштуваннях («Домовик памʼятає: …»). Історія чату обрізається за токенами.
4. **Агентні tools** (read-only + дії в межах апки) з §6.3, плюс `get_focus_stats` і `get_dev_status` (P-01). Цикл tool calling обмежений (≤ 4 кроки) з таймаутом.
5. **Провайдери:** Ollama (локально, приватно) → рекомендований за замовчуванням, Claude Haiku → дешевий хмарний варіант, OpenAI-compatible → усе інше (LM Studio, OpenRouter).
6. **Evals.** Набір 20–30 сценаріїв («що гальмує?», «скільки місця?», injection у заголовку вікна, відповідь у характері, мова uk/en) з перевірками: викликав правильний tool, не вигадав цифр, тримає персону, укладається в довжину. Запуск: `pnpm eval --provider ollama`. Для резюме це сильний пункт: «LLM-фічі з eval-набором у CI».
7. **Голос (TTS/STT)** — поза v1, але інтерфейс `Voice` закласти.

## 4. Арт (AD-)

### AD-01 · Арт-спайк перед кодом поведінки
Персонаж — обличчя проєкту і перше, що побачить рекрутер у README-гіфці. Повторюємо підхід Cossack Kin: арт-бібліотека генераторів кодом + палітра + gate `art-director`, і **один персонаж до рівня «гарно»** раніше за все інше.
- Розмір: 32×32 або 48×48 логічних px при цілому масштабі ×2–×4 (фіксує спайк). 64×64 для такого стилю забагато.
- Мінімальний набір анімацій: `idle` (2 варіанти), `walk`, `sit`, `sleep`, `drag`, `fall`, `land`, `talk`, `think`, `happy`, `worried`, `wave`.
- FX кодом поверх: «Zzz», краплі поту, серця, знак питання (ідеї з `pixelfx`).

### AD-02 · Три вбудовані персонажі у v1 — забагато
**Пропозиція:** v1 = Домовик, відшліфований + імпорт GIF/скін-паків. Кіт Пиріжок і Пікселька — після релізу, коли пайплайн генерації доведено.

## 6. Цінність для резюме

Твоє резюме сильне в бекенді (черги, воркери, планувальники, масштабування). Цей проєкт додає те, чого там бракує, і кожен пункт можна довести кодом:
- **Desktop/Electron:** багатопроцесна архітектура, typed IPC, hardening (sandbox, CSP, contextIsolation), пакування й автооновлення через CI.
- **Real-time рендер і стейт-машини:** Pixi, фізика, детерміноване ядро з тестами, виміряні бюджети CPU/RAM.
- **Прикладний AI:** агентний шар з tool calling, structured output, памʼять, провайдер-агностичність, локальні моделі, **evals**, захист від prompt injection, MCP-сервер.
- **AI-native процес:** репозиторій із закомітченою конфігурацією агентів/скілів/рулсів (`docs/AI-WORKFLOW.md`) — третій проєкт у тому ж стилі після Applyra і Cossack Kin.

Чернетка рядка в CV: *«Built a cross-platform AI desktop companion (Electron, TypeScript, PixiJS): deterministic behavior engine, provider-agnostic LLM agent with read-only tool calling and eval suite, local MCP server reacting to Claude Code hooks; < 2% idle CPU.»*

## 9. Склад персонажів (чернетка, на затвердження)

### Як зробити 10 персонажів реальними
10 персонажів × ~20 анімацій — це ~200 анімацій. Малювати кожну окремо нереально.
**Рішення: модульний піксельний «риг».** Усі персонажі мають спільний скелет 32×32 (голова, тулуб, руки, ноги, хвіст/крила як слоти). Анімація описується **один раз** як рух частин. Персонаж — це набір частин + палітра + 3–5 фірмових анімацій зверху.
Генерується кодом (як у Cossack Kin), а `art-director` приймає кожен кадр.

Порядок:
- M-ART — риг + 3 персонажі;
- M1–M3 — ще 3;
- до v1 — усі 10.

### Персонажі
| # | Архетип | Характер | Фірмові заняття / реакції |
|---|---|---|---|
| 1 | **Демониця-економка** (ріжки, фартух, мітла) | строга перфекціоністка, таємно турботлива | змітає «пил» з верхнього краю вікна; RAM > 90% → «який безлад!»; сварить за пізню годину |
| 2 | **Лис-ніндзя** (маска, пухнастий хвіст) | гіперактивний, хвалько | телепортується між вікнами з клубом диму; визирає з-за краю екрана; ловить курсор |
| 3 | **Дух-мечник** (плащ із туману) | спокійний, говорить афоризмами | медитує під час Pomodoro; одним ударом «розрубує» курсор; стоїть на варті у fullscreen-кутку |
| 4 | **Кам'яний голем-силач** | флегматик, усе для нього «надто легко» | віджимається на панелі задач; «тримає» вікно, що падає; CPU 100% → навіть не помітив |
| 5 | **Піратка-шукачка скарбів** (підзорна труба) | авантюристка | шукає «скарби» (найбільші файли на диску через tool); пливе в чашці кави по екрану |
| 6 | **Відьма-учениця** | невпевнена, вчиться | варить зілля, закляття смішно не вдаються; впали тести → «закляття зламалось» |
| 7 | **Вогняна саламандра** | емоційна, запальна | розгорається разом із CPU; кип'ятить собі чай; гасне, коли засинає |
| 8 | **Ретро-робот на колесі** | педантичний, любить цифри | сканує систему променем; «заряджається» разом із ноутбуком; антена блимає під навантаженням |
| 9 | **Глітч-слайм** (розсипається на пікселі) | трикстер, мешканець коду | «ламає» край вікна; **радіє багам і червоним тестам**, сумує від зелених (комічний антипод) |
| 10 | **Кіт-лицар** у завеликих обладунках | шляхетний боягуз | охороняє екран; лякається різкого курсора; «б'ється» з курсором миші |

### Спільні для всіх
- **Курсор:** стежить очима; лякається різкого руху; ганяється; погладжування (коло курсором); тицьнути; drag з теліпанням ніг; кидок з інерцією та відскоком.
- **Місце:** ходить по панелі задач; сидить або спить на краю вікна; лізе по боковій стороні вікна; визирає з-за краю екрана; падає, коли вікно закривається.
- **Побут:** читає, п'є чай, позіхає, потягується; реагує на час доби (ранок, ніч).
- ~~Між персонажами~~ — скасовано рішенням D-8 (на екрані один персонаж).
- **AI:** у кожного своя `persona`, набір емоцій і фразові шаблони uk/en. LLM говорить у характері (§3).
